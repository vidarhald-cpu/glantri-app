# Combat Action Rule Inventory

Source document: `docs/source/combat/merged_3968_3980.pdf`

Status: extraction and classification only. Do not implement directly from this document without a follow-up formula/table verification pass against the scanned source pages.

## Extraction Notes

- The source PDF is a 13-page scanned/image PDF. Local text extraction was not available, so this inventory was made from visual page review.
- Page references below use the PDF image page number. The first page is the table of contents; the source text itself begins on PDF page 2.
- Some source tables are partially cut at page edges or continue between pages. Those entries are marked as requiring a second-pass transcription before implementation.
- This document intentionally separates action declaration concepts from resolution rules, because the current app is still building declaration and round-manager workflows before full attack resolution.

### Feint-Attack lifecycle

`Finte - angrip` uses one canonical Phase-1 feint proposal and one ordinary Phase-2 attack opportunity against the same target. The proposal waits for the actor's normal initiative-ordered A1 turn; there is no separate pre-roll feasibility gate. Description and ordinary M1 situational modifiers carry fictional plausibility and weapon-difficulty adjudication.

For a movement feint, the attacker rolls Dodge with Dexterity. For a weapon feint, the server derives the combat skill from the selected committed weapon source and uses Dexterity; the client cannot substitute an unrelated skill. The defender rolls their highest relevant close-combat skill with Intelligence. Player ownership applies to each roll, GM proxy rolling uses the same command, and only the roller receives that roll's private calculation.

After both rolls, the table creates a proposal rather than changing combat state immediately. The GM may accept or adjust the two proposed values and add a private review note. Committing completes the Feint A1 slot (`✓`) and creates deterministic generated rows: attacker DB/Parry in Phase 1; linked defender Skill/OB and DB/Parry in Phase 2. Equal linked defender values display as one OB/DB consequence while remaining separate calculation buckets. These rows last for the current round under the existing phase-scoped modifier rules. The attacker Phase-1 row affects only later Phase-1 interactions, not completed actions; exact-tie-group activation remains part of the broader within-phase modifier sequencing work. The Phase-2 attack then enters the existing M2, i2, A2, parry, location, critical, damage, event, and undo pipeline.

Undo follows the command stack: undoing commit removes the linked feint rows and restores the reviewed proposal with both rolls; undoing the second roll removes the table proposal but preserves the first roll; undoing the first roll restores the action-turn roll state. Legacy feasibility commands and records remain readable for historical compatibility, but new declarations do not create them. A GM adjustment is authoritative for this proposal only and does not mutate imported participant effects or unrelated manual/generated rows.

### Adjust Distance-Attack lifecycle

`Juster avstand - angrip` declares one opponent, a requested pair distance, and one ordinary
Phase-2 attack opportunity. The maneuver opens at the actor's initiative-ordered A1 turn. The
defender may allow it, which creates an automatic successful proposal without rolls, or oppose it.
For opposition, the GM first assigns an optional whole-number `0..4` adjustment to either side;
then both participants use the existing Dodge/open-ended-roll path. A strict higher attacker total
wins, so a tie leaves the distance unchanged.

After allow or both rolls, the GM reviews the standard outcome and may commit any valid pair
distance. Commit updates the shared live distance edge immediately, marks A1 complete (`✓`), and
continues normal Phase-1 ordering. Phase 2 remains scheduled on success or failure and uses the
committed (or unchanged) distance through the existing M2/i2/A2 attack pipeline. Moving closer
creates DB/Parry `-2` for Phase 1 only; moving farther creates no automatic penalty. Later SU
distance control starts from the live committed edge but remains a separate proposal lifecycle.

Each response, adjustment, roll, proposal, and commit is command/event-backed. Undoing commit
restores the prior edge and reviewed proposal; earlier undo steps remove only their downstream
maneuver facts. Player projections expose each participant's own Dodge calculation and the shared
outcome, while GM-only notes and the other participant's dice remain private.

## Implementation Boundary For Next Passes

- Do not wire these action rules directly into the current combat declaration UI yet.
- First useful implementation candidates are generated phase modifiers for the action catalogue already present in the UI:
  - `Angrip - parer`
  - `Parer - angrip`
  - `Angrip - Angrip`
- Before implementing any numeric rule, create a structured table source with page reference, exact bands, and tests.
- Distance, perception, combat experience, simultaneous attack, disarm, and feint all require supporting state that does not yet exist in the encounter round model.

## Open Questions / Ambiguities

- The source uses percentage-style modifiers throughout, but each future implementation should confirm whether a value is a raw modifier input to the workbook percentage helper or a direct roll modifier.
- Missile defense and multiple-attack parry rules reference adjustment tables not included in this extracted action source.
- Distance/reach rules depend on weapon reach and movement modifiers; this source references those concepts but does not fully define their data model.
- Some Norwegian/English mixed table labels should be preserved in canonical table metadata so future implementation can trace back to the scanned text.
